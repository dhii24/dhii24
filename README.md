## 🚀 Featured Project

### 🗂️ [Project Management Tool](https://github.com/dhii24/project-management-tool)

**Live Demo:** [Frontend](https://project-management-tool-kappa-eight.vercel.app/) · [Backend Health Check](https://project-management-backend-fvnt.onrender.com/health)

**React · Node.js · Express.js · MongoDB Atlas · Redis/Valkey · Cloudinary · Docker · Docker Compose · Nginx · GitHub Actions**

A full-stack, workspace-based project management application inspired by tools like Trello and Jira. It supports collaborative Kanban boards, team workflows, and project analytics.

**Key Features & Engineering Highlights**

- Built workspace collaboration with member invitations and role-based access control (**Admin, Manager, Member**).
- Implemented secure REST APIs with JWT authentication, password hashing, resource-level authorization, and protected routes.
- Added Redis-backed rate limiting to registration and login endpoints: **5 requests per IP, per endpoint, per 15-minute window**.
- Implemented workspace-specific caching for analytics endpoints using Redis-compatible Valkey, with a **60-second TTL** and cache invalidation after card mutations.
- Observed an approximately **56% response-time reduction** in a sample analytics request (**493 ms → 216 ms**); this is a sample measurement, not a formal benchmark.
- Built analytics endpoints using MongoDB aggregation and added pagination, search, and database indexes for frequently queried data.
- Integrated Cloudinary for file storage while keeping attachment metadata in MongoDB.
- Containerized the frontend and backend with Docker and Docker Compose; configured Nginx as a reverse proxy in the containerized deployment.
- Maintained separate development and production container workflows, including development bind mounts and backend hot reload.
- Hardened Docker containers by running as a non-root user and dropping unnecessary Linux capabilities.
- Reduced the backend Docker image size by approximately **82% (1.71 GB → 313 MB)** through image and dependency optimization.
- Built a GitHub Actions CI pipeline with backend checks across **Node.js 24 and 26**, frontend lint/build checks, Docker image builds, Docker Hub publishing, dependency caching, and Docker layer caching.
- Configured Vercel and Render deployments to wait for the required GitHub Actions checks to pass.

**Deployment Architecture**

| Component | Platform |
|---|---|
| Frontend | Vercel |
| Backend API | Render |
| Database | MongoDB Atlas |
| File storage | Cloudinary |
| Cache / rate limiting | Valkey |
| CI | GitHub Actions |
| Container images | Docker Hub |
